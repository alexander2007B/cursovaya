# Архитектура и инварианты

Три слоя: React → HTTP JSON API Express → MongoDB через Mongoose. Фронтенд собирается Vite и раздаётся Express с того же origin; в разработке Vite проксирует `/api`.

## Коллекции

- `users`: имя, нормализованный уникальный email, телефон, хеш пароля, роль, даты.
- `cars`: марка, модель, номер (unique), класс, стоимость, залог, пробег, технический статус, архив, версия блокировки.
- `rentals`: владелец, автомобиль, снимок имени и тарифа, интервал [from,to), допуслуги, сумма, статус, история переходов.
- `maintenances`: автомобиль, сотрудник, узел, процент износа, пробег, заключение, дата.
- `events`: автор, операция, идентификатор сущности, описание, время.
- `sessions`: серверные сессии с TTL, управляются connect-mongo.

В MongoDB нет внешних ключей SQL. Ссылочную целостность обеспечивают серверные команды. Архивирование вместо физического удаления сохраняет историю. Суммы — целые рубли; коммерческая система должна хранить копейки. Тариф в заявке фиксируется: последующее изменение цены автомобиля не меняет существующую аренду.

## Защита от двойной аренды

Каждая команда бронирования, смены статуса аренды, архивирования или изменения авто в транзакции сначала увеличивает `cars.lockVersion`. Конкурирующие транзакции пишут один документ: одна фиксируется, другая повторяется драйвером на новом снимке. В повторе проверяется пересечение: `existing.from < new.to && existing.to > new.from`. Блокирующие статусы: new, confirmed, active. После отмены/завершения интервал свободен. Автоматического срока истечения новой заявки пока нет; её нужно подтвердить или отменить.

`В аренде` вычисляется из активной аренды; в `cars.status` сохраняется только available/maintenance/broken. Это предотвращает расхождение статуса машины и заявки. Будущая аренда не делает технически исправный автомобиль неисправным.

Выдача разрешена с даты начала до даты возврата, только если авто исправно и нет другой активной аренды. Возврат обновляет пробег, запрещая уменьшение. Просроченная активная аренда блокирует выдачу другому клиенту; диспетчер должен урегулировать фактический возврат. Штрафы за просрочку автоматически не начисляются.

## Права и сессии

Публичная регистрация создаёт только клиента. Сессия содержит id пользователя, роль перечитывается из БД. Права действуют на сервере, включая прямые API-запросы. Пароли bcrypt, cost=12; длина ограничена 72 байтами UTF-8. Cookies HttpOnly + SameSite=Lax; production добавляет Secure. Изменяющие запросы требуют токен из `/api/auth/session`; при входе сессия регенерируется. Ограничение входа: 40 попыток за 15 минут на IP процесса. В кластерном развёртывании нужен общий rate-limit store.

## Область проверки

22 серверных теста и 5 браузерных сценариев. Покрытие относится к исполняемым серверным файлам, не ко всему React-интерфейсу и не к скриптам. Проверена локальная MongoDB с одним узлом; отказоустойчивый кластер, восстановление backup, разные браузеры и публичный HTTPS не проверялись.
