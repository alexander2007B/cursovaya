# Размещение Python-версии на Render

Существующий Static Site не умеет выполнять Flask. Для новой версии создаётся отдельный **Web Service**. Пока он не проверен, прежний сайт продолжает работать на старом размещении.

- Repository: alexander2007B/cursovaya.
- Branch: python-only.
- Language / Runtime: Python 3.
- Root Directory: пусто.
- Build Command: `pip install -r requirements.txt`.
- Start Command: `gunicorn --bind 0.0.0.0:$PORT --workers 1 --threads 8 app:app`.
- Health Check Path: `/api/health`.
- Environment: APP_MODE=demo, APP_ENV=production; SESSION_SECRET — случайная строка от 32 символов (Generate).

Можно использовать render.yaml как Blueprint. Выбор платного тарифа и оплата в эту настройку не входят. Наличие файла конфигурации не означает, что сервис уже создан или опубликован.

После сборки откройте выданный Render URL: главную, каталог, прямую ссылку на карточку, вход и регистрацию. В демо заявки сохраняются в браузере каждого посетителя, а не в общей базе.

Для полной версии: APP_MODE=full, MONGODB_URI с replica set и аутентификацией, SESSION_SECRET, HTTPS; фотографии uploads должны находиться на постоянном диске либо во внешнем файловом хранилище после отдельной настройки. Локальный Docker Compose сам по себе не создаёт MongoDB на Render. Не используйте localhost:27017 как адрес внешней базы.

Когда новый сервис проверен, можно перенести собственный домен и настроить автоматическое развёртывание ветки. Данные браузерного демо другого домена автоматически не переносятся.

Для новой общей базы первичный администратор создаётся отдельной командой python -m norde.admin, с собственным email, именем, телефоном и скрытым вводом пароля. Автоматическое создание открытого production-администратора отсутствует.
