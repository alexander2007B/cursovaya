# Руководство по установке и сопровождению NORDÉ

Редакция от 26 ноября 2026 года. Полная версия: React, Express, MongoDB. Статическая демоверсия предназначена для просмотра интерфейса и сохраняет данные только в браузере.

## 1. Требования и подготовка

Для полной версии нужны Node.js 22 или выше, npm, Git и Docker с Compose. Порты по умолчанию: 3000 - приложение, 27017 - локальная MongoDB; 5173 используется Vite в режиме разработки. Для браузерных тестов необходим Chromium.

Получите репозиторий https://github.com/alexander2007B/cursovaya, ветку main. Выполняйте команды из его корня. Установка точных зависимостей производится по package-lock.json, а не произвольным обновлением библиотек.

```sh
git clone --branch main https://github.com/alexander2007B/cursovaya.git
cd cursovaya
npm ci
npm run setup:env
```

Скрипт setup:env создаёт .env только при его отсутствии. Он записывает случайный SESSION_SECRET, адрес локальной MongoDB, порт и параметры учебного запуска. Существующий .env не перезаписывается. Рабочие секреты нельзя включать в Git или архив документации.

## 2. Запуск полной версии

```sh
npm run db:up
npm run seed
npm run build
npm start
```

После готовности сервера откройте http://localhost:3000. Команда db:up запускает MongoDB как одноузловой replica set с именем rs0. Это необходимо для транзакций. Если используется внешний кластер, его адрес задаётся в MONGODB_URI и он также должен поддерживать транзакции.

Seed разрешён только вне production при SEED_DEMO=true. Он добавляет отсутствующие учебные записи, обновляет стандартные иллюстрации и прежнее имя стандартного менеджера на «Дмитрий». Заявки не удаляются. Пользовательские имена, отличающиеся от старого стандартного значения, не подменяются.

Для разработки выполните npm run dev: одновременно запускаются сервер и Vite. Запросы /api и /uploads проксируются на сервер. Обычная производственная сборка создаёт dist, который Express раздаёт с того же origin, что и API.

## 3. Учебные аккаунты

После seed доступны admin@avtobaza.test, manager@avtobaza.test и client@avtobaza.test с паролем Avtobaza2026!. Это открытые демонстрационные реквизиты. Для реального размещения с общей базой нужен отдельный набор пользователей без этих аккаунтов, собственный SESSION_SECRET и MongoDB с аутентификацией.

При NODE_ENV=production сессионные cookie требуют HTTPS. Настройки доверия прокси должны соответствовать фактической схеме развёртывания. До публичной эксплуатации отдельно проверяются HTTPS, резервное восстановление, ограничения входа и права доступа.

## 4. Запуск и размещение демоверсии

```sh
npm ci
npm run demo
```

Откройте http://127.0.0.1:5173. Демо не использует MongoDB и не требует .env. Вход действует отдельно для каждой вкладки. Автомобили и заявки находятся в localStorage; их удаление или кнопка сброса возвращает исходный набор.

Для статического хостинга соберите именно demo, иначе клиент будет пытаться обращаться к отсутствующему API:

```sh
npm run build:demo
```

Загрузите содержимое dist в public_html: index.html должен лежать непосредственно в public_html, а не во вложенной папке dist. Сохраните прежнюю стартовую страницу хостинга как резервную копию, если она есть. Для Apache настройте DirectoryIndex index.html и перенаправление маршрутов React на index.html через .htaccess. Реальные файлы изображений, шрифтов и скриптов должны обслуживаться без подмены.

Рекомендуется HTTPS: функции Web Crypto, используемые демо, требуют безопасного контекста. После выпуска сертификата проверьте главную страницу, прямое открытие каталога, вход, создание заявки и перезагрузку страницы. Настройка нового сервиса не означает, что публикация на Timeweb уже завершена: на дату редакции её результат не подтверждён.

## 5. Проверки Selenium, pytest и Postman

Для автоматизации нужны Python 3.12+, Chromium или Google Chrome, зависимости requirements-test.txt и Newman из npm ci. Полный порядок приведён в docs/TESTING.md. Выполняйте команды из корня репозитория.

```sh
python3 -m venv .venv
. .venv/bin/activate
python3 -m pip install -r requirements-test.txt
npm run db:up
npm run test:all
```

В Windows используйте python вместо python3 и активируйте .venv\Scripts\Activate.ps1. Если имя python3 отсутствует, основной runner вызывается как python scripts/run-quality.py. Путь к Chrome при необходимости задаётся CHROMIUM_PATH.

test:all сам собирает клиент, запускает выделенный сервер :3001 и последовательно выполняет Postman/Newman, pytest и нагрузку. Порт должен быть свободен. Перед началом пересоздаётся только avtobaza_e2e. Рабочая база не очищается; данные, которые нужно сохранить, в учебной базе не размещают.

Новый прогон от 26.11.2026: 6 доменных, 5 интеграционных и 4 браузерных случая pytest, всего 15; 15 HTTP-запросов и 15 утверждений Newman. Selenium проверяет регистрацию с согласиями, сохранение профиля, галерею, панель, выделение текста за модальное окно и загрузку четырёх фото. Процент покрытия JavaScript этим набором не измерен.

Для отдельных сценариев сначала запустите npm run test:server, затем в другом терминале выполните npm test, npm run test:api или npm run test:e2e. Многократные входы на старом процессе могут получить HTTP 429: это работа лимита. Для полного повторения используйте новый процесс через test:all, не отключая защиту.

Нагрузка npm run test:load использует только локальную полную версию: GET /api/cars, 10 и 50 потоков, identity и gzip, по три повтора по 5 секунд. Не запускайте её одновременно с другими тестами. Она не характеризует статический Render или предельную мощность сервиса. JSON каждого повтора, XML и журналы сохранены в docs/reports/selenium-pytest-postman/.

Postman: импортируйте docs/postman_collection.json, оставьте baseUrl = http://127.0.0.1:3001 и запустите коллекцию по порядку. Cookie, CSRF и идентификаторы передаются автоматически. Зафиксированный прогон выполнен Newman, командным исполнителем коллекций Postman.

## 6. Сохранение и восстановление данных

MongoDB хранится в Docker volume mongo_data. Команда npm run db:down останавливает контейнер, сохраняя том. Не добавляйте -v: это удаляет данные. Фотографии, загруженные на сервер, находятся в uploads/ и копируются отдельно от базы.

Для резервной копии применяются штатные mongodump и mongorestore. Следует остановить изменяющие операции либо организовать согласованный снимок базы и uploads. Архив .env с секретами хранится отдельно с ограниченным доступом. Восстановление сначала проверяется на отдельном экземпляре, затем сверяются число заявок, ссылки на машины и доступность фотографий. Автоматизированный регламент восстановления в проект не включён.

## 7. Диагностика

ECONNREFUSED 127.0.0.1:27017: выполните docker compose ps и проверьте готовность контейнера. Ошибка Transaction numbers ... replica set означает запуск standalone MongoDB либо неверное подключение к rs0.

Ошибка входа после включения production обычно требует проверки HTTPS и cookie. Ошибка CSRF устраняется обновлением сеанса и повторным входом; отключать защиту для обхода ошибки не следует. Неверные или пустые данные проверяются до выполнения бизнес-команды.

Если статический сайт показывает заглушку хостинга, проверьте DirectoryIndex и расположение index.html. Если прямая ссылка на каталог даёт 404, проверьте правила SPA в .htaccess. Если интерфейс ожидает /api, пересоберите с --mode demo. Блокировка домена на уровне хостинга или Cloudflare требует отдельной проверки и не исправляется заменой файлов React.
